# هدية / HADIYA — منصة تبرّع بالعملات الرقمية

نسخة وظيفية (functionally-equivalent clone) مبنية على بنية GoFundMe: حملات، صفحات حملات،
تحديثات، تعليقات، لوحة منظّم، لوحة كولكتر، وتسجيل دخول بتوقيع المحفظة.

**الفرق الجوهري:** الاعتماد الكامل على العملات الرقمية، ودفع رسوم **متدرّجة** في نفس معاملة
التبرّع، وباقي المبلغ يذهب **مباشرة** إلى محفظة الجهة المستفيدة (لا يمرّ بحساب المنصة).

| البند | القيمة |
|---|---|
| رسوم المنصة | متدرّجة: ٩٪ حتى ٢٠٠$ ← ٧٪ فوق ٢٠٠$ ← ٥٪ فوق ٣٠٠$ ← ٣٪ فوق ٤٠٠$ |
| ما يصل للجهة المستفيدة | ٩١٪ … ٩٧٪ — في نفس المعاملة (ذري) |
| رسوم إنشاء حملة / تحديثات | ٠ |
| الشبكات | Base، BNB Smart Chain، Polygon، Ethereum (+ Base Sepolia للاختبار) |
| الرموز | ETH / BNB / POL (أصلية) + USDC / USDT / USDT0 (بخانات متفاوتة — مُتحقَّق منها) |
| قاعدة البيانات | SQLite المدمج في Node 24 (`node:sqlite`) — بلا خدمات خارجية |
| المتصفح | Express + EJS (تصيير من الخادم) + JS خالص للواجهة |

## ٢) تغيير الاسم (اسم مختلف عن GoFundMe)

كل الهوية في ملف واحد: `config/brand.js`

```js
module.exports = {
  name: 'HADIYA',       // الاسم اللاتيني
  nameAr: 'هدية',       // الاسم العربي
  tagline: '…',
  platformFeeBps: 900,  // أقصى نسبة (٩٪)
  minFeeBps: 300,       // أدنى نسبة (٣٪)
  feeTiers: [           // جدول الشرائح — عدّله كما تشاء
    { maxUsd: 200,   bps: 900 },
    { maxUsd: 300,   bps: 700 },
    { maxUsd: 400,   bps: 500 },
    { maxUsd: Infinity, bps: 300 },
  ],
  …
};
```

**مهم:** النسبة تُفرض داخل العقد (`contracts/DonationSplitter.sol`)، لذلك أي تغيير في
`feeTiers` يستلزم: (1) تعديل الثوابت في العقد، (2) إعادة نشر العقد، (3) إعادة ضبط
الشرائح على السلسلة بـ `npm run set:tiers`.

## ٣) الرسوم المتدرّجة — كيف تُفرض؟

| قيمة التبرّع (دولار) | رسوم المنصة | يصل للجهة المستفيدة |
|---|---|---|
| حتى ٢٠٠$ | ٩٪ | ٩١٪ |
| فوق ٢٠٠$ حتى ٣٠٠$ | ٧٪ | ٩٣٪ |
| فوق ٣٠٠$ حتى ٤٠٠$ | ٥٪ | ٩٥٪ |
| فوق ٤٠٠$ | ٣٪ | ٩٧٪ |

### نماذج الرسوم القابلة للتبديل

`config/brand.js` → `feeMode`:

| الوضع | النتيجة | عند النشر |
|---|---|---|
| `tiered` (الافتراضي) | ٩/٧/٥/٣٪ حسب المبلغ | `min=300 max=900` |
| `flat` | نسبة ثابتة ٩٪ لكل تبرّع | `min=900 max=900` |
| `zero` | **٠٪ — "١٠٠٪ يذهب للقضية"** | `min=0 max=0` |

الحدود تُثبَّت داخل العقد عند النشر (`immutable`) — أي أن تغيير النموذج يتطلّب **نشر عقد
جديد**، وهو مقصود: المتبرّع يعرف نسبة المنصة من البايت كود نفسه.

⚠️ **تنبيه على نموذج "٠٪":** إن ذهبت لرسوم صفرية، المنصة لا تحتاج عقدًا أصلًا — التبرّع
المباشر إلى محفظة الجهة المستفيدة يكفي، لكن عندها **لا تستطيع المنصة تحصيل أي نسبة** من
التبرّعات المباشرة. العقد هو ما يسمح بالتحصيل الذري بلا حضانة أموال.

آلية الفرض:

1. **داخل العقد**: دالة `feeFor(token, amount)` تختار الشريحة حسب **الوحدة الأصلية** للمبلغ
   (وليس حسب نسبة يختارها المتبرّع)، فالمتبرّع لا يستطيع التلاعب بالنسبة.
2. **عتبات لكل رمز**: `setTiers(token, t1, t2, t3, enabled)` يحدد حدود الشرائح بالوحدة
   الأصلية. skript `npm run set:tiers` يحسبها من سعر الصرف الحالي ويكتبها على السلسلة.
   للأصول المتقلّبة (ETH/POL) يجب إعادة تشغيله دوريًا (كل بضعة أسابيع) لتحديث العتبات.
3. **الحدود**: الحد الأقصى ٩٪ والحد الأدنى ٣٪ — لا يمكن تجاوزهما من أي طرف.
4. **ال_events**: حدث `DonationReceived` يحمل `feeBps` المستخدمة فعليًا، وهي المصدر
   الموثوق الذي يسجّله الخادم (لا يثق بأي رقم يرسله المتصفح).
5. **الواجهة**: تعرض النسبة المتبقّعة لحظة الدفع عبر `GET /api/fee-for` (تقرأ من العقد
   إن كان منشورًا، وإلا تحسبها من جدول الشرائح).

```bash
npm run compile:contracts     # solc → contracts/build/DonationSplitter.json
npm run deploy:contracts      # افتراضيًا Base Sepolia (CHAIN_ID=84532)
CHAIN_ID=8453 npm run deploy:contracts
CHAIN_ID=8453 npm run set:tiers        # ضبط شرائح الرسوم على الشبكة
```

### خطوات النشر (Base)

1. `Copy-Item .env.example .env` → ضع `PRIVATE_KEY` و `COLLECTOR_ADDRESS`.
2. `npm run compile:contracts`
3. `CHAIN_ID=84532 npm run deploy:contracts` → عنوان على Base Sepolia (مجاني، غاز fake).
4. `CHAIN_ID=84532 npm run set:tiers` → ضبط عتبات الشرائح.
5. اختبر بتبرّع صغير من محفظة على Sepolia.
6. `CHAIN_ID=8453 npm run deploy:contracts` + `CHAIN_ID=8453 npm run set:tiers` → mainnet.

عنوان العقد يُخزَّن تلقائيًا في قاعدة البيانات ويصلح كل الصفحات فورًا.

## ٤.٤) IPFS للمحتوى (اختياري)

القصص والصور يمكن تثبيتها على IPFS فيصير المحتوى قابلًا للقراءة من شبكة لا تتحكّم بها
المنصة — حتى لو تغيّر الموقع أو أُغلق.

```bash
PINATA_JWT=<jwt> npm run ipfs:pin -- --slug=hlth-aml
```

السكربت يثبّت مستند JSON (القصة + بيانات الحملة) ويطبع الـ CID ويحفظه في
`campaigns.story_cid`، فتظهر صفحة الحملة رابطه للمتبرّعين.

> الـ CID هو Merkle root للمحتوى: إن تغيّر المحتوى، تغيّر الـ CID. (التخزين خارج المنصة
> هو ما يجعل هذا ذو قيمة — لا تسجّل CID على-chain إن لم تكن تخطط لتثبيت الميزة.)

## ٤) منع وضع عناوين المحافظ داخل وصف الحملة

القاعدة: **يُمنع** وضع أي عنوان محفظة (0x + 40 خانة، أو عنوان مبتور، أو اسم ENS) في:

- عنوان الحملة
- السطر الوصفي (subtitle)
- القصة (story)
- تحديثات الحملة (updates)
- تعليقات الحملة (comments)

عنوان المحفظة يُكتب **فقط** في خانة «محفظة الجهة المستفيدة» (`charity_wallet`)،
وهو الحقل الوحيد الذي يظهر للجميع على صفحة الحملة.

التنفيذ:
- **الخادم (ملزم)**: `src/lib/validate.js` → `assertNoWalletAddress()`، يُستدعى داخل
  `models.createCampaign` و`models.addUpdate` و`models.addComment`. الطلب يُرفض بـ 400
  ورسالة عربية واضحة.
- **المتصفح (تجربة أفضل)**: تحذير فوري أثناء الكتابة + منع الإرسال.
- **بصمة المعاملة مسموحة** (`0x` + 64 خانة) لأنها ليست عنوان محفظة.

## ٤.٢) قائمة المراجعة (لا KYC — ضوابط بديلة)

لأن المنصة **لا تطبّق KYC**، أضفت ضابطًا يقلّل الاحتيال:

- كل حملة جديدة تُنشأ بحالة `pending_review` → **لا تظهر في `/discover` ولا تقبل تبرعات**.
- المشرف يراها في **لوحة الكولكتر → قائمة المراجعة** ويوافق/يرفض.
- بعد الموافقة → `active` (تظهر للعموم وتستقبل تبرعات).
- زر التبرّع يظهر «بانتظار المراجعة» معطّلًا قبل الموافقة.

الحالات: `pending_review` · `active` · `paused` · `closed` · `rejected`.

## ٤.٣) ضوابط أمنية مطبَّقة

| الضابط | التفصيل |
|---|---|
| `.gitignore` | `data/` (قاعدة البيانات فيها `session_secret`) و `.env` (فيه `PRIVATE_KEY`) مستبعدة من Git |
| عمق التأكيد | لا يُعتمد تبرّع قبل `MIN_CONFIRMATIONS` كتل (افتراضي ٥) — حماية من انقلاب السلسلة |
| انتهاء المعلّق | تبرّع بلا معاملة يُوسم فاشلًا بعد `PENDING_EXPIRY_MIN` (افتراضي ١٢٠ د) فلا ينمو الجدول |
| قراءة السجلات على دفعات | `LOG_CHUNK_BLOCKS` (افتراضي ٢٠٠٠) + تثبيت المؤشر بعد كل دفعة — لا تنقطع المزامنة عند حدود RPC العامة |
| استهلاك الـ nonce | يُحذف بعد التوقيع → لا يمكن إعادة تشغيل رسالة موقّعة |
| تحديد معدّل | على كل نقاط النهاية العامة + قفل محاولة تسجيل دخول الإدارة (٨ محاولات / ١٥ د) |
| اكتشاف ERC20 المباشر | البحث في أحداث `Transfer` — لا يُفقد التبرّع المباشر بتوكن |
| شفافية تسعير | إذا تعذّر السعر يظهر «—» بدل $0 مضلّل |
| CSP مشدّد | `script-src 'self'` — أُزيل كل معالجات `onclick` inline واستُبدلت بسمات `data-*` |
| حقن SQL | كل الاستعلامات عبر prepared statements (بلا أي concatenate لقيم المستخدم) |
| XSS | EJS يهرّب المخرجات؛ الإدراج الديناميكي في JS يمرّ عبر `escapeHtml()` |
| Mass assignment | قائمة حقود مسموحة صريحة في `models.updateCampaign` |

## ٤.٤) لوحة الإدارة (`/admin`) — حماية من الاختراق

### الدخول — ثلاث طرق

| الطريقة | كيف | متى تستخدمها |
|---|---|---|
| **حساب (اسم مستخدم + كلمة مرور)** | `POST /api/admin/login` | daily — أسرع طريقة، وتعمل بلا محفظة |
| **مفتاح إدارة** | `POST /api/admin/session` | استعادة/تشغيل آلي |
| **توقيع محفظة** | `/sign-in` | متى كان العنوان ضمن قائمة المشرفين |

#### بيانات الدخول الافتراضية (غيّرها فورًا)
```
اسم المستخدم : admin
كلمة المرور  : ooKg3yNs2PHffu8NSnxo
```
> كلمة المرور مخزّنة في `.env` (وليس في Git) وتُنشأ تلقائيًا عند أول تشغيل.
> **غيّرها أول دخول**: `لوحة الإدارة ← الأمان ← تغيير كلمة مرور حسابي`
> أو ولّد حسابًا جديدًا من نفس القسم (تظهر كلمة المرور مرة واحدة فقط).

### كيف تُحمى كلمات المرور
- **Argon2id** (مدمج في Node 24) — ٦٤ ميغابايت ذاكرة × ٣ تكرارات (≈٣٠٠ms لكل محاولة).
- **salt فريد** لكل كلمة مرور (١٦ بايت).
- **pepper سري** من `PASSWORD_PEPPER` في `.env` يُخلط كـ `secret` — لو سُرقت قاعدة البيانات
  وحدها، البصمات لا تكفي لتخمين الكلمة.
- **قفل الحساب** ١٥ دقيقة بعد ٥ محاولات فاشلة.
- **منع كشف وجود الحساب**: حساب غير موجود يحسب بصمة وهمية بنفس الزمن + نفس رسالة الخطأ.
- **سياسة**: ١٠ خانات على الأقل، رفض الكلمات الشائعة، ورفض المطابقة لاسم المستخدم.
- الجلسة في كوكي `HttpOnly` + `SameSite=Lax`، وكل الطلبات المُعدِّلة تتطلّب رمز CSRF.

### محفظة المنصة (لكل متبرّع)
حساب المتبرّع له **طريقتان** — ويمكن استخدامهما معًا:

| الطريقة | كيف | ما تحتاجه |
|---|---|---|
| **اسم مستخدم + كلمة مرور** | `/register` ثم `/login` | اسم مستخدم + كلمة مرور (Argon2id) |
| **توقيع المحفظة** | `/sign-in` | محفظة فقط — بلا كلمة مرور ولا بريد |

- `/create` يوجّه غير المسجّلين إلى `/login?next=/create` (استكمال بعد الدخول).
- **حساب باسم مستخدم يجب ربط محفظة** قبل إنشاء حملة — لأن العنوان هو المالك على السلسلة
  (والربط يتطلّب **توقيع رسالة** من صاحب المحفظة، فلا يمكن ربط محفظة غيرك).
- `/account` يعرض حملاتك وتبرّعاتك، ويتيح ربط/فك ربط المحفظة وتغيير كلمة المرور.
- لا نحفظ أي سر من المستخدم على الإطلاق.


### الأقسام
| القسم | الوظيفة |
|---|---|
| **نظرة عامة** | KPIs + حالة العقد على السلسلة + أعداد الحملات والتبرعات |
| **الرسوم** | يعرض **الحدود الحقيقية على السلسلة** (`MIN/MAX_FEE_BPS` immutable) + محرّر الشرائح |
| **مراجعة الحملات** | موافقة/رفض/إيقاف + **تعديل** + **توثيق/إلغاء توثيق** + **حذف** (سبب إلزامي) + تفاصيل كل حملة |
| **قاعدة البيانات** | إحصاءات، `PRAGMA integrity_check`، متصفّح قراءة (قائمة بيضاء)، **تصدير CSV** |
| **فحص السلامة** | يعيد حساب كل المجاميع، يقارن **محفظة كل حملة في الداتا بما هو في العقد**، ويكشف أي نسبة لا تطابق شريحتها |
| **سجل التدقيق** | كل إجراء حسّاس مع الفاعل والوقت و IP |
| **الأمان** | الجلسات، حسابات الإدارة، **المستخدمون** (تعطيل/توليد كلمة مرور)، **إعدادات المنصة**، محافظ المشرفين |

| الإجراء | المسار | ملاحظة |
|---|---|---|

| تغيير محفظة المستفيد | نفس المسار | **مسموح فقط إن لم تكن الحملة مسجّلة على العقد** (غيرها → 409) |
| توثيق / إلغاء توثيق | نفس المسار | شارة «موثّق» |
| حذف الحملة | `POST /api/admin/campaigns/:slug/delete` | **سبب إلزامي** + سجل تدقيق + حذف تبرعاتها |
| موافقة/رفض/إيقاف | `POST .../status` | |
| موافقة جماعية | `POST /api/admin/campaigns/bulk-status` | |
| حذف تبرّع | `POST /api/admin/donations/:id/delete` | مع سبب |
| حذف تحديث/تعليق | `POST /api/admin/content/:kind/:id/delete` | مع سبب |
| إدارة المستخدمين | `GET /api/admin/users` · `POST .../toggle` · `.../reset-password` | كلمة المرور الجديدة تظهر مرة واحدة |
| إعدادات المنصة | `GET/POST /api/admin/settings` | محفظة الكولكتر/المشرف (مع تحذير immutability) |

> **ما لا يستطيعه المشرف أبدًا**: تغيير محفظة جهة مستفيدة مسجّلة على العقد (العقد يمنعه)،
> تجاوز حدود الرسوم (immutable)، أو تجاوز النسب المسموح بها في محرّر الرسوم (يرفض بـ 400).

### 🔒 الضمانة الأساسية: لا أحد يغيّر عناوين الحملات
**على مستوى العقد**، لا على مستوى الموقع:

```solidity
function setCharity(uint256 id, address charity) external {
    Campaign storage c = _campaigns[id];
    if (msg.sender != c.organizer) revert NotOrganizer();  // المنظّم فقط
    ...
}
```

- **المنصّة (owner) تستطيع**: إنشاء الحملات، إيقافها (لحماية المتبرّعين من احتيال)، ضبط شرائح الرسوم ضمن الحدود الثابتة.
- **المنصّة لا تستطيع** تغيير محفظة الجهة المستفيدة — **حتى لو سُرق مفتاحها أو حسابها بالكامل**.
- تغيير العنوان يوقّعه **منظّم الحملة في محفظته**؛ اللوحة تولّد له `calldata` جاهزًا فقط.
- دالة `campaign(id)` عامة على السلسلة → أي جهة تستطيع مقارنة ما تعرضه المنصة بالContract.

### 🔒 الضمانة الثانية: لا أحد يأخذ رسومًا فوقMax
- `MIN_FEE_BPS` و `MAX_FEE_BPS` **immutable** داخل العقد → لا يمكن رفعها بعد النشر.
- محرّر اللوحة **يرفض** أي نسبة خارج نطاق العقد (يرجع `400`).
- 금액 التبرّع يُقرأ من **الأحداث على السلسلة**، لا من المتصفح — فلا تلاعب بالرسوم.
- فحص السلامة يقارن نسبة كل تبرّع مسجّل بالشكل المحسوب من الشريحة ويبلّغ عن أي اختلاف.

## ٦) تدفّق التبرّع

1. المتبرّع يختار المبلغ والعملة من نافذة "تبرّع الآن" (المعاينة تعرض الشريحة لحظيًا).
2. المتصفح يتصل بمحفظة EIP-1193 (MetaMask وأي محفظة متوافقة) — أو ينسخ العنوان ويرسل من تطبيقه.
3. إن كان العقد منشورًا: `approve` (للعملات) ثم `donate()` / `donateToken()`.
4. يرسل المتصفح `tx_hash` إلى `POST /api/donations`.
5. الخادم يقرأ الـ receipt وحدث `DonationReceived` **من السلسلة** ويسجّل المبلغ الإجمالي،
   الرسوم (مع `feeBps` المستخدمة)، الصافي، والمتبرّع.
6. `pollPending` يعيد التحقق كل ٢٠ ثانية، و`syncSplitterEvents` يستورد أي تبرّع تمّ على
   العقد مباشرة (حتى لو لم يمرّ بالواجهة).

إن لم يكن العقد منشورًا بعد → تحويل مباشر إلى محفظة الجهة المستفيدة، وتُسجَّل الرسوم
كـ«غير محصّلة» في دفتر المنصة (لأن المنصة لا تستطيع خصم نسبة من مبلغ وصلها كاملًا).

## ١٠) نصوص صريحة يجب أن تعرفها قبل الإطلاق

- **لا استرداد تلقائي:** مدفوعات العملات الرقمية نهائية. أي استرداد = معاملة جديدة من
  محفظة المنصة أو الجهة المستفيدة ولا يمكن ضمانه. النص ظاهر في الموقع.
- **الرسوم المتدرّجة**: الشريحة تُحدَّد بقيمة التبرّع بالدولار وقت الدفع. عتبات الرموز
  المتقلّبة تُحدَّث دوريًا، فقد تتغيّر شريحة borderline بين تحديث وآخر.
- **"موثّق" = مراجعة مستندية يدوية** من فريق المنصة، وليست تدقيقًا ماليًا ولا ضمانًا.
- **الضرائب:** التبرّع بالعملات الرقمية قد يخلق التزامًا ضريبيًا للمتبرّع.
- **KYC/AML:** المشروع الحالي **لا يطبّق** KYC ولا فحص قوائم عقوبات. في أغلب الدول يجب
  الإبلاغ عن تبرّعات فوق حد معيّن — طبّق ذلك قبل استقبال أموال حقيقية.
- **لا تحجز المنصة أي مبلغ نيابة عنك** ولا تحتفظ بأموالك.
- **النصوص القانونية** (`/terms`, `/privacy`) قوالب عامة — استبدلها بمراجع قانونية.

## ١١) الترجمة / Language switch

الواجهة تدعم لغتين: **العربية (افتراضي)** و **الإنجليزية**. التبديل يتم عبر زر «ع/EN» في الترويسة (الزاوية العلوية اليمنى).

### كيف يعمل
- زر اللغة يبدّل القيمة المخزّنة في `localStorage` تحت المفتاح `hadba_lang` (`'ar'` أو `'en'`).
- عند التحميل، سكربت `theme.js` (في `<head>`) يقرأ `hadba_lang` ويطبّق اللغة **قبل أول رسم** — لا يوجد وميض (anti-flash).
- محرك i18n (`public/js/i18n.js`) يعمل بثلاث طبقات:
  1. **قاموس العناصر** (`data-i18n`): كل عنصر يحمل `data-i18n="key"` يُستبدل نصه بالقيمة من كائن `EN` في `i18n.js`.
  2. **قاموس العبارات** (`HADIYA_PHRASES`): بعد تطبيق الطبقة الأولى، يمرّ `translateTree()` على كل عقد النص في الصفحة، وأي نص يطابق مفتاحًا في `window.HADIYA_PHRASES` (عربي → إنجليزي) يُترجم تلقائيًا — هذا يغطّي النصوص الثابتة في القوالب دون الحاجة لوضع `data-i18n` على كل عنصر.
  3. **دالة `t(key)`**: متاحة في JS العام عبر `window.HadiyaI18n.t('نص عربي')` — تُستخدم في الكود المولّد ديناميكيًا (مثل معاينة الرسوم في نافذة التبرّع).
- عند تبديل اللغة، يُطلق حدث `hadiya:lang` على `document` مع `detail: { lang }` — أي كود JS يمكنه الاستماع لهذا الحدث وإعادة رسم مكوناته باللغة الجديدة.

### محتوى الحملات بلغتين
عند إنشاء/تعديل حملة، يمكن تعبئة الحقول الاختيارية:
- `title_en` — عنوان الحملة بالإنجليزية
- `subtitle_en` — السطر الوصفي بالإنجليزية
- `story_en` — القصة الكاملة بالإنجليزية

دالة `localizedCampaign(campaign, lang)` في `src/view-helpers.js` تُرجع الحقول الإنجليزية عند `lang='en'` إذا كانت مُعبّأة، وتتراجع للعربية تلقائيًا عند غيابها. في `lang='ar'` تُرجع العربية دائمًا.

**Language switch / الترجمة** — the header holds a **ع / EN** toggle. The choice is persisted in `localStorage` (`hadba_lang`) and applied before first paint via `theme.js` (no flash). The i18n engine (`i18n.js`) works in three layers: (1) `data-i18n` keys mapped to `EN` dictionary; (2) phrase dictionary `HADIYA_PHRASES` (Arabic → English) auto-translates any matching text node; (3) `window.HadiyaI18n.t(key)` helper for dynamic JS. A `hadiya:lang` event is dispatched on language change. Campaign content can be bilingual via optional `title_en`, `subtitle_en`, `story_en` fields — `localizedCampaign()` falls back to Arabic when English fields are empty.

## ١٢) تخصيص المظهر / Theming

لوحة التخصيص تفتح بزر 🎨 في الترويسة. الإعدادات تُحفظ في `localStorage` تحت المفتاح `hadba_theme` وتُطبّق **قبل أول رسم** عبر سطر `theme.js` في `<head>` (بلا وميض — anti-flash).

### الخيارات
| الخيار | القيم |
|---|---|
| **الثيم** | فاتح (Light) · داكن (Dark) · رملي (Sand) · منتصف الليل (Midnight) · **تلقائي** (Auto — حسب نظام التشغيل) |
| **لون التمييز (Accent)** | ٨ ألوان جاهزة (أخضر، أزرق، بنفسجي، وردي، كهرماني، تركوازي، قرمزي، نيلي) + **لون مخصّص** (Color picker حر) |
| **حجم الخط** | صغير (٩٣٪) · عادي (١٠٠٪) · كبير (١٠٨٪) |
| **الكثافة (Density)** | مضغوط (Compact) · مريح (Comfortable) — يغيّر المسافات العمودية `spacing` |
| **استعادة** | زر واحد يعيد كل الإعدادات للافتراضي |

### آلية العمل
- لون التمييز (`--brand`) يقود الواجهة كاملة: أزرار، روابط، أشرطة تقدّم، شارات، تدرجات، حلقات التركيز (`--ring`).
- الألوان المشتقة تُحسَب حسابياً: `--brand-ink` (نص مقروء فوق اللون)، `--brand-soft` (خلفيات خفيفة)، `--brand-muted`.
- الوضع الداكن **ليس انعكاساً** — له لوحة ألوان خاصة (خلفيات، حدود، ظلال) مصممة بشكل مستقل.
- كل متغيّرات CSS تُطبّق على `:root` و `[data-theme="dark"]` — التبديل يتم بتغيير `data-theme` على `<html>`.

**Theming / تخصيص المظهر** — the 🎨 button opens a panel with 4 themes (Light, Dark, Sand, Midnight, Auto), 8 preset accent colors + custom picker, font size (93/100/108%), and density (Compact/Comfortable). Settings persist in `localStorage` (`hadba_theme`) and are applied before first paint via inline `theme.js` in `<head>` (no flash). The accent color drives the entire UI via computed CSS variables (`--brand`, `--brand-ink`, `--brand-soft`, `--ring`). Dark mode has a dedicated palette, not a simple inversion.
